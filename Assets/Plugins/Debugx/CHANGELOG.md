# Changelog

## [Unreleased]
### Removed
- Unused editor helpers: `DebugxEditorLibrary`, the `GUILayoutEx` `ButtonColor` / `ButtonCyan` / `ButtonGray` / `ToggleLeft*` helpers and unused `ButtonRed` / `ButtonYellow` overloads, `GUIUtilityEx.PushTint` / `PopTint`, the `EditorWindow` / custom-style `FadeArea` constructors, and `GUIStyleEx.TitleStyle1` / `BackgroundTex` / `ColorGg`. Debugx never used them; if your own editor code did, copy them into your project.
- The editor-quit hook that unregistered the member color callbacks. It did nothing useful on quit, and if another handler cancelled the quit, new members were left with a white color until the next script reload.

### Changed
- **Project files moved out of the plugin folder.** The settings asset is now created at `Assets/DebugxSettings/Resources/DebugxProjectSettings.asset`, and the generated `DebugxLogger.cs` at `Assets/DebugxSettings/`, next to a `Debugx.asmref` that still compiles it into the `Debugx` assembly. The package no longer ships either file. As a result, a `.unitypackage` upgrade can no longer overwrite your members and generated methods, a UPM install no longer ends up with two `DebugxProjectSettings` assets in Resources (builds could load the wrong one), and asmdef code can call `DebugxLogger` under UPM too. Existing projects keep working: a settings asset created by an older version is still used where it is, and an old generated `Assets/Plugins/Debugx/Runtime/DebugxLogger.cs` is removed and regenerated at the new location when the editor loads. The `DEBUGX_IN_UPM` define is no longer needed and has been removed. A warning is shown if the project contains more than one `DebugxProjectSettings` asset.
- **The plugin's own Resources** (the runtime Console's `Console` PanelSettings, its theme and the severity icons) moved into a `Resources/Debugx/` subfolder and are loaded as `Debugx/…`, so they can't collide with a game's own Resources assets named `Console`, `icon_error`, … (either side could load the other's). A PanelSettings named `Console` directly under `Resources`, as older docs asked for when the bundled one was missing, is still used as a fallback. The bundled PanelSettings also referenced a theme that doesn't ship with the package (every start logged "No Theme Style Sheet set to PanelSettings Console"); it now uses the bundled `DebugxRuntimeTheme`.
- **Editor Console** keeps at most 50,000 logs by default (the oldest are dropped), adjustable per user in Editor panel > View > Buffer Capacity. The unlimited buffer from 2.4.3 made every refresh walk all of the session's logs, so a long Play session got steadily slower and could run the editor out of memory. New logs now refresh the list at most about 10 times a second, and not at all while the window's tab is hidden (it catches up when shown); the in-game runtime Console's refresh is throttled the same way.
- **Editor Console** "Replace Native Console" now only takes effect while a Debugx Console window is open. The Debugx Console only captures logs while it is open, so replacing the native Console while it was closed hid every log produced meanwhile (clicking the status bar opened a Debugx Console without it, and a Clear then erased it from the native store as well).

### Fixed
- Rebuilt `DebugxLog.dll` (2.4.0.2) with `DEBUG_X` defined. It had been compiled without it, so every call the DLL made to its own `[Conditional("DEBUG_X")]` methods was stripped: `DebugxBurst.Log` / `LogWarning` / `LogError` did nothing, and Debugx's own warnings (unknown member key or signature, `SetMemberEnable` called too early) never appeared. The unknown key / signature warnings are now printed once per distinct message (reset when `Debugx.OnAwake` runs), so a missing member doesn't add a warning to every one of its logs. The "logOutput over" notice is now a plain log instead of a warning.
- **Log file output** no longer wipes the previous session's log. When a session never reached `RecordOver` (a crash, an editor crash, or the OS killing the app on mobile), the next start opened `DebugxLog.log` with `FileMode.Create` and truncated it. The leftover file is now archived first, named after its last write time; if it can't be moved (for example another game instance holds it), the new session appends to it instead of truncating it.
- **Log file output** now records logs from worker threads. It listened to `Application.logMessageReceived`, which Unity only raises for main-thread logs, so anything logged from a `Task`, a thread or a network callback never reached the file; it now uses `logMessageReceivedThreaded`. Lines from other threads show `-` instead of a frame number.
- **DebugxManager** now starts logging before the first scene loads. It used to initialize only after the first scene's `Awake` / `OnEnable` had run, so their logs never reached the log file, and member switches set there with `SetMemberEnable` were reset when it initialized. The manager itself is still created after the scene loads, so a manager (or subclass) placed in the first scene is still the one used. A second `DebugxManager` (for example in a scene that is loaded again) is now removed instead of resetting the runtime switches, restarting the log file and, when destroyed, stopping file recording for the rest of the session.
- **Editor Console** compile errors / warnings could be missing. The mirror read Unity's native Console store through its filtered view, so if warnings (or errors) were hidden in the native Console, or its search box held text — both persist even while that window is closed — the matching compile messages never appeared in the Debugx Console, and hiding them later removed the ones already shown. The scan now reads the unfiltered store and restores the native Console's filter afterwards. The re-scan after a compile / Clear is now a few spaced passes instead of a one-second deadline, so a long import right after a domain reload can no longer let it expire without scanning, and it no longer reads the whole native store on every editor tick.
- **Debugx Console** (Editor and in-game) search highlighting was misplaced or missing when a message contained a `<` that is not a rich-text tag — generics like `List<int>`, `hp <= 0`, `<null>`. The highlighter skipped every `<…>` (and stopped at an unclosed `<`) while the search matched the text with only real rich-text tags removed; both now skip exactly the same tags.
- **Runtime Console** could be drawn under the game's own UI Toolkit panels and lose clicks to them: the sort order was set on the `UIDocument`, which only orders documents inside one panel. The shipped `Console.asset` PanelSettings now has Sort Order 30000. The panel also fits high-DPI phones: it no longer has a 320 px minimum width (wider than a ~400 ppi phone's logical width in portrait), and the detail pane takes 35% of the panel instead of a fixed 200 px (taller than the whole panel in landscape).
- **Runtime Console**: once the buffer was full, a list scrolled up to read older logs kept sliding away — every new log evicted the oldest and shifted every row (about 17 rows a frame at 1,000 logs/s). New logs no longer refresh the list while it is scrolled up; it catches up as soon as you scroll back to the bottom, and reopening the panel jumps to the newest logs.
- **Runtime Console**: `DebugxRuntimeConsole.SetVisible(bool)` is now the static method the README documents. It was an instance method on a private instance, so the documented call didn't compile; call it as `DebugxRuntimeConsole.SetVisible(true)`. The README (CN / EN / JA) is corrected as well: the default buffer capacity is 4000, the popup is named Settings (it also holds the buffer capacity), Clear must be held for a second, and the toggle key / gesture work with the new Input System too.
- **Runtime Console** got three fixes the Editor Console already had; the code behind them now lives in the shared `DebugxLog.Console` layer, so both consoles use the same implementation: Copy no longer includes Debugx's own `DebugxLogger` forwarder frames; Members > None now hides everything, including members that start logging after the popup was opened or while the list was empty (the old "drift" re-filter logic is gone); timestamps use a culture-invariant `HH:mm:ss`.
- **Project Settings / Preferences > Debugx**: the "DEBUG_X is not configured" warning read the Standalone platform's defines, while the editor compiles with the active platform's. With Android active and `DEBUG_X` defined only for Android it warned that Debugx would not work (it did); with `DEBUG_X` defined only for Standalone it stayed silent while every log call was compiled out. The check now follows the defines the editor actually compiles with.
- **Debugx Console** stack traces: the name-based fallback that hides the generated `DebugxLogger` forwarder frame when reflection can't see `[HideInCallstack]` (e.g. under aggressive AOT stripping) looked for `DebugxLog.DebugxLogger`, but the class is generated in the global namespace, so the fallback never matched.
- **DebugxLogger generation** no longer rewrites the file (and recompiles every script) after a git pull. The generated header mixed line endings and the up-to-date check compared raw text, so a checkout with `core.autocrlf` always looked changed; the file is now generated with `\n` line endings and line endings are ignored in the comparison.
- **Member colors**: a new member's automatic color ignored Master's hue, so with the default setup the next member came out almost the same color as Master; "Automatically Reassign Colors" started at hue 0, also right next to Master. Master's hue is now avoided in both. "Adapt Color By Editor Skin" no longer turns white / black colors (Normal) into a pinkish red that matched Master, and on a first run the default members now get skin-appropriate colors (Normal was white even on the Light skin).
- **Preferences > Debugx** and other per-user editor settings are now stored in EditorPrefs scoped to the project. They were in PlayerPrefs, which in the editor are the game's own prefs, so a game calling `PlayerPrefs.DeleteAll()` (a typical "reset save") wiped every member mute and log toggle; and the Auto Save / fold states were machine-wide EditorPrefs, so changing them in one project changed them in every project. Values saved by older versions are still picked up. Builds keep using PlayerPrefs (`DebugxStaticData.RuntimeConsoleEnabled` etc.).
- **Project Settings > Debugx** info box now says what actually applies where. It claimed these settings affect everyone's project, but in the editor the log switches and log output options come from each person's Preferences; only builds use the project values. (Behavior unchanged, matching the README's "editor = Preferences" rule.)
- **Runtime Console** no longer disappears for good after its GameObject is deactivated and activated again: it kept its old UI state while `UIDocument` had built a fresh, empty root (so the panel was never rebuilt), and it started over with an empty buffer. It now rebuilds the panel and keeps its logs.
- **Debugx Console** (Editor and in-game) with Collapse on: once the buffer was full, the selection and detail pane cleared while the row was still on screen — a collapsed row is represented by its oldest entry, and when that entry was evicted the selection (kept by entry id) no longer matched. Collapsed rows are now matched by their group, so the selection stays (also when toggling Collapse).
- **Debugx Console** list rows show at most 512 characters (and the in-game detail pane at most 10,000); Copy still copies the full text. A log carrying a huge payload (JSON, a dump) used to become one giant label rebuilt on every bind or repaint, and in the in-game overlay could exceed UI Toolkit's per-element vertex limit.
- **Debugx Console** search, collapse and Copy now treat rich-text tags the caller put into a Debugx message the same as in other logs: `Debugx.Log(1, "<b>Boss</b> spawned")` is found by searching "Boss spawned" and copies as plain text (the tags used to stay in the text used for search / collapse / Copy).
- **Editor Console**: if saving its logs before a domain reload failed (for example out of memory with huge payloads), the rest of the window's teardown was skipped and the closed window kept collecting logs until the next reload. The save is now guarded, and the kept logs are capped at 2,000,000 characters as well as 2,000 entries.
- **Project Settings > Debugx** member keys. A new member took the smallest free key, so after a member was deleted the next new one inherited its key — the deleted member's leftover `Debugx.Log(key, …)` calls and every teammate's mute for that key silently applied to the new member. New keys are now always one above the highest key ever issued. Duplicate keys (for example after two branches each added a member) are now reported: an error on the settings page and a warning when the editor loads, and `DebugxLogger` is not regenerated until each member has its own key.
- **Project Settings > Debugx**: Delete Member now asks for confirmation — a misclick removed the member's `DebugxLogger` methods at once and broke every call site. Undo / redo of a settings change is now saved and re-applied (and `DebugxLogger` regenerated) like any other edit; before, undoing a deletion restored the member only in memory and the generated code stayed broken. With Auto Save off, the Save Asset button no longer greys out after a script reload while changes are still unsaved.
- Changing any Debugx setting during Play (a member color, a Preferences toggle, …) no longer resets the runtime switches: `EnableLog`, `EnableLogMember`, Only Key and per-member switches set from the Console panel or with `SetMemberEnable` are kept, and members added meanwhile start with their defaults. Regenerating `DebugxLogger` during Play is now postponed until Play ends, so a signature or key edit no longer triggers a script recompile (and, with "Recompile And Continue Playing", a domain reload) mid-session.
- **Runtime Console** Settings popup: the Capacity and Only Key number fields applied every keystroke. Typing "8000" over "4000" first set the capacity to 8 and permanently dropped all but 8 logs, and typing "12" into Only Key passed through key 1, muting every other member meanwhile. Both fields (and the Editor panel's Only Key field) now apply on Enter or when focus leaves.

## [2.4.5] - 2026-11-08
### Fixed
- **Editor Console** list rows looked blurry compared to the native Console, especially Chinese text. On Unity 2022.3, UI Toolkit can only render editor text through SDF font atlases (no hinting), which smears at the 11px row size; the native Console uses IMGUI's OS-rasterized hinted glyphs. Each row's timestamp and message are now drawn with IMGUI, so they are exactly as sharp as the native Console. Search-match highlighting is kept, now drawn as a blue box behind the match (IMGUI can't render `<mark>`).

## [2.4.3] - 2026-07-12
### Added
- **Debugx Console** search now highlights the matched substring inside each list row (in both the Editor window and the in-game runtime overlay), so a row shows *why* it matched rather than just that it did.
- **Debugx Console** shows a centered `No results for "…"` message over the list when the search text matches nothing (in both the Editor window and the runtime overlay), instead of leaving a blank list. It appears only while the search box is non-empty; a member/type filter that empties the list still shows nothing, matching the native Console.
- **Editor Console** gets an opt-in **Replace Native Console** toggle (Editor panel > View, per-user, off by default). When on, Unity's native Console is closed whenever it opens — clicking the log in the editor's bottom status bar, `Ctrl+Shift+C`, the Window menu, or a restored layout — and the Debugx Console opens instead. Works even while the Debugx Console is closed. While on, every Debugx Console clear (manual, Clear on Play / Recompile / Build) also clears Unity's native log store, so the bottom status-bar message is reset too (compile errors stay, as with the native Clear). The status-bar message itself already shows Debugx logs, since they go through `Debug.Log`.
### Changed
- **Editor Console** display cap removed. The log ring buffer now grows on demand (doubling from 64) up to an effectively unlimited retention cap (`int.MaxValue`) instead of evicting the oldest entries at a fixed limit. Storage is still allocated lazily, so an idle console costs nothing until logs actually accumulate. The in-game runtime Console stays bounded (4000).
- Rebuilt `DebugxLog.dll` (2.4.0.1): the log message's `ToString()` is now evaluated before the compose lock is taken (so a same-thread re-entrant log can no longer corrupt the shared `StringBuilder`), the color-tag trim uses a precompiled regex, and file recording publishes its directory path and writer under a single lock. `DebugxBurst` is now a static class.
### Fixed
- **Editor Console** detail pane text color no longer breaks when the editor skin is switched. Lines without a `<color>` tag (stack frames, uncategorized / compile logs) reused a one-time-cached default text color; switching Dark/Light does not reload the script domain, so the stale color persisted (e.g. black text on the dark skin). The detail style is now rebuilt when the skin flips, and its default text color is set explicitly from the current skin. Member `<color>` messages were never affected.
- A batch of robustness fixes: editor-skin color values are now queried live instead of cached (so they can't go stale across a skin switch), regex matching uses `CultureInvariant`, the log directory path is derived via `Directory.GetParent`, the generated `DebugxLogger` method-name de-duplication was hardened, and the `DEBUG_X` define check now matches exactly.
- **Editor Console** "Clear on Play" now clears when leaving Edit mode (as the native Console does) instead of on `EnteredPlayMode`, which fires after `Awake`/`OnEnable` and could wipe the play session's startup logs.

## [2.4.2] - 2026-07-11
### Fixed
- **Editor / runtime Console** stack traces no longer leak Debugx's own forwarder frames. The raw stack the Console receives via `Application.logMessageReceived` is *not* run through Unity's `[HideInCallstack]` stripping — that only happens inside Unity's own Console window — so the generated `DebugxLogger` forwarding frame stayed in the trace and double-clicking a log jumped to the forwarder instead of the caller's business code. `StackTraceParser` now reproduces the stripping itself (reflecting on each frame's method, cached by `Type|Method`, with a name-based fallback for the generated forwarder to survive AOT) and skips those frames in stack display, double-click navigation, and stack copy.
- **Editor Console** occasionally missed compile errors/warnings that Unity's native Console showed. The live channel dropped compile messages and relied on a single `LogEntries` scan at `compilationFinished` to re-add them, but `LogEntries` flushes asynchronously and out of sync with that event — if the one scan ran before an error was flushed, the error was lost for good. Reworked into an absorb-and-reconcile model: the live channel no longer drops compile messages (they appear immediately as Uncategorized), the mirror reconciles against `LogEntries` as the source of truth, and a 1-second bounded re-scan window closes the async-flush race.
- **Editor Console** compile errors did not reappear after **Clear**. Clear now pumps the compile mirror again, re-reading the errors still present in the editor console and re-injecting them.
### Changed
- **Error icon** changed from an exclamation mark to an "x", for clearer distinction from the info icon.

## [2.4.1] - 2026-07-10
### Fixed
- **Debugx Console** tail auto-scroll: when the list was stuck to the bottom, newly added logs did not always reach the very bottom. `ScrollToItem` ran in the same frame the rows changed — before the ScrollView had recomputed its content height / scroll extent — so it landed a row short, and never corrected once the log stream stopped. It now re-scrolls after the content geometry is recomputed. Fixed in both the Editor window and the in-game runtime overlay.
- **Runtime Console** detail/stack pane scrolled too far per mouse-wheel notch; reduced the wheel step (`ScrollView.mouseWheelScrollSize`) for gentler, near line-by-line scrolling.
- **Editor Console** stack-frame hyperlink now underlines only the `path:line` inside the trailing `(at …)` instead of the whole frame line, matching Unity's native Console.
- **Editor Console** detail pane clipped the last wrapped line when scrolled to the bottom (its content height was under-measured); added trailing padding so the last line fully clears the viewport.

## [2.4.0] - 2026-07-05
### Added
- **Debugx Console** — a dedicated, member-aware log viewer that replaces reliance on Unity's native Console, in two forms sharing one capture / filter / collapse model layer:
  - **Editor window** (Window > Debugx > DebugxConsole): captures all Unity logs (non-Debugx grouped as "Uncategorized"); filter by member / type / Debugx-only / search; collapse duplicates; timestamps; script-only or full stack view; multi-select copy; double-click source navigation; Error Pause; compile-log mirroring; Clear on Play / Recompile / Build; and cross-recompile & domain-reload persistence. A collapsible **Editor** side-panel hosts the runtime switches (EnableLog / EnableLogMember / Only-Key) and test toggles.
  - **In-game runtime overlay** (`DebugxRuntimeConsole`, UI Toolkit): a touch-friendly overlay that self-mounts under `DEBUG_X` when enabled and a `Console` PanelSettings asset is present in a Resources folder — the same model layer with member / source / net-tag filters, search-match highlighting, and multi-select copy. Summon via backquote key, three-finger tap, a floating button, or the public `DebugxRuntimeConsole.SetVisible(bool)` API (the key / tap gestures require the legacy Input Manager).
- `Debugx.OnRawLog` — a structured log event carrying full member metadata (key / signature / color / header / net tag / LogType / message / final text), so consumers such as the Debugx Console can read logs with full member context instead of re-parsing formatted text. Near-zero cost: the value-type payload isn't even constructed when there are no subscribers.
- `Debugx.IsDebugxTagged(string)` — a helper that centralizes the `[Debugx]` tag check (kept in sync with `DebugxTag`).
### Removed
- Retired the legacy on-screen IMGUI log overlay (`LogOutput.DrawGUI` and its `DebugxManager.OnGUI` driver), superseded by the Debugx Console above, along with its project settings `drawLogToScreen` / `restrictDrawLogCount` / `maxDrawLogs`. **Breaking:** this drops those public `DebugxProjectSettings` fields, so any external code referencing them must be updated. The feature defaulted off, so runtime behavior is otherwise unchanged.
